## 1. What this is

A Go CLI that searches the **Los Angeles Community College District** class
schedule across all 9 colleges by scraping the public **PeopleSoft Campus
Solutions guest portal** — no login, no official API. It was generated by the
"printing-press" CLI generator, then heavily hand-built (the scraping client,
HTML parsers, store schema, and every user-facing command are hand-written Go;
the generator supplied the scaffold + framework commands).

- **Binary/module name:** `laccd-class-search-pp-cli` (the `-pp-cli` suffix is a
  generator artifact; the binary works fine, but see §9 if you want to rename).
- **Status:** fully working and verified end-to-end against live Fall 2026 data.
  Shipcheck PASS (7/7), live dogfood 60/60, scorecard 71/100 (Grade B).

## 4. The reverse-engineered portal contract (the most important knowledge here)

Target: `https://mycollege-guest.laccd.edu/psc/classsearchguest/EMPLOYEE/HRMS/c/COMMUNITY_ACCESS.CLASS_SEARCH.GBL`
Oracle PeopleSoft Campus Solutions 9.2, classic (non-Fluid) Class Search.

**Reachability:** plain `standard_http`, no anti-bot, no clearance cookie. The
one requirement: a **cookie-jar warm-up GET** of the component URL before any
deep-link (a fresh request with no cookies gets a 302 to a cookie-check page).
The client handles this once per process (`internal/laccd/client.go` `warmup`).

**Three request shapes the client uses:**

1. **List sections (deep-link GET)** — the primary path, no stateful POST:
   ```
   GET {base}?Campus={college}&strm={term}&subj={subject}[&catalogid={3-digit}]
   ```
   - Returns the `SSR_CLSRCH_MTG1` results grid as HTML.
   - **With `catalogid`:** all sections of one course (complete).
   - **Without `catalogid`:** a COLLAPSED whole-subject sample (~17 sections
     across N courses, NOT all sections). The current `SearchScope` path does
     not request or parse this sample. It first calls the official schedule
     discovery endpoint
     `https://services.laccd.edu/apps/api/classschedule/listing/{college}/{term}?subjectlist={subject}`,
     normalizes/deduplicates/sorts its catalog numbers, then fans out one
     catalog-scoped request per selected course. `catalogid` is zero-padded to
     3 digits (`035`); 4-digit CCN numbers pass through.
   - `--max-courses N` bounds whole-subject discovery-driven fan-out to the
     first N catalogs in that deterministic order. `0` is unbounded; negative
     values are usage errors. A bounded result reports `courses_scanned`,
     `courses_total`, and `truncated` and must not be persisted by `sync` as a
     complete scope.

2. **Section detail / seats (stateful ICAction POST)** — the only way to get
   exact seat counts. Flow: warm-up → deep-link GET the results page (harvest
   `ICSID`, `ICStateNum`, all hidden inputs) → POST the same URL with
   `ICAction=MTG_CLASS_NBR$N` (the section's row index). Returns the class-detail
   page with `SSR_CLS_DTL_WRK_*` seat fields.

3. **Subject list (subject-lookup POST)** — set CAMPUS+STRM on the entry form,
   POST `ICAction=CLASS_SRCH_WRK2_SSR_PB_SUBJ_SRCH$0` with the magic
   `ICBcDomData=UnknownValue`. Returns `SSR_CLSRCH_SUBJ_SUBJECT$N` codes +
   `SUBJECT_TBL_DESCRFORMAL$N` names.

**Parsed grid fields** (`$N` = 0-based row index): `MTG_CLASS_NBR$N` (class nbr,
also the detail link), `MTG_CLASSNAME$N` ("P01-LEC Regular" → section/component/
session), `MTG_DAYTIME$N`, `MTG_ROOM$N`, `MTG_INSTR$N`, `MTG_TOPIC$N` (dates),
and the status icon (`PS_CS_STATUS_{OPEN,CLOSED,WAITLIST}_ICN`, nearest icon
before each row).

**Detail fields:** `SSR_CLS_DTL_WRK_ENRL_CAP / ENRL_TOT / AVAILABLE_SEATS /
WAIT_CAP / WAIT_TOT / UNITS_RANGE / SSR_DESCRSHORT (status)`.

### Reference data (confirmed live)

- **Colleges (`Campus=`):** ELAC, LACC, LAHC, LAMC, LAPC (Pierce), LASC, LATTC,
  LAVC, WLAC. (`ITV` and `LACCD`=district are excluded — not searchable colleges.)
- **Institution is always `LACCD`** (single shared instance). The college is the
  `Campus` dimension — that's why cross-college comparison works.
- **Terms (STRM):** 4-digit `2` + 2-digit year + term digit (2=Spring, 6=Summer,
  8=Fall). Only currently-registerable terms appear — **fetch them live, don't
  hardcode** (`terms` command). Live at build time: `2268`=Fall 2026, `2266`=Summer 2026.
- **Subject codes can contain spaces** (`ADM JUS`, `AFRO AM`) — never strip them.
  CCN subjects are separate codes (`ANTH`=CCN vs `ANTHRO`=legacy), flagged by a
  `(CCN)` description suffix.

### Parser gotchas (will bite you if you forget)

- **`$NN$` field suffixes are dynamic per session** (e.g. `CLASS_SRCH_WRK2_STRM$35$`
  one load, `$173$` another). Match by prefix/regex, never hardcode the number.
- PeopleSoft **double-quotes `<option value="...">` and omits `</option>`**, but
  **single-quotes form inputs**. The option regexes are quote-agnostic and read
  to the next tag.
- Cell values embed raw **CR/LF** (`LEC\r\nRegular`); `stripTags` normalizes
  control whitespace (fixed after an output-review caught `\r` leaking into the
  `session` field).
- The search **POST** path (not used by default) silently no-ops without
  `ICBcDomData=UnknownValue`; large results show an "over N classes" interstitial
  needing `ICAction=%23ICSave`. The deep-link GET path avoids both — see the
  discovery report in manuscripts for the full POST recipe if ever needed.

## 6. Command inventory

**Domain (hand-built):** `search`, `section <class-nbr>`, `colleges`, `terms`,
`subjects --college --term`, `sync --college --term --subject`.
**Novel (hand-built):** `compare-colleges --subject --catalog --term`,
`watch <class-nbr>`, `ccn <subject> <number> --college --term`,
`schedule build <class-nbr>...`, `changed --since`.
**Framework (generated):** `doctor`, `agent-context`, `version`, `which`, `api`,
`profile`, `feedback`, `import`, `workflow`, `completion`.

Global flags worth knowing: `--json` / `--agent` (agent mode), `--select`
(dotted-path field filter, e.g. `--select sections.class_nbr,sections.status`),
`--data-source auto|local|live`, `--db`, `--dry-run`, `--rate-limit`, `--timeout`.
Whole-subject `search` defaults to `--max-courses 30`; `sync` defaults to
`--max-courses 50`. Pass `--max-courses 0` for an unbounded resync.

Every hand-written command: verify-friendly (`--dry-run` exits 0 before any IO),
typed exit codes (2=usage, 5=api, etc.), `IsVerifyEnv()`/`IsDogfoodEnv()`
short-circuits so the test matrices don't make false failures, and a
`// pp:data-source` annotation.

## 7. Data model

- `sections` (generated typed table, keyed on JSON `id` = class_nbr) — the mirror.
- `section_detail` (class_nbr PK) — latest seat counts per section.
- `seat_snapshots` (append-only history of status+seats per observation) — powers
  `watch` (diff vs prior) and `changed` (new/dropped/status-flip over a window).
- `resources_fts` / `sections_fts` — FTS5 offline search.

`search`/`sync` populate `sections` and append grid snapshots; `section`/`watch`
add detailed seat snapshots. Whole-subject `sync` writes an additive,
version-2 `sync_state` completeness marker containing `completeness_version=2`,
`discovery_source=laccd-schedule-api`, ordered `catalogs_json`,
`courses_total`, `courses_scanned`, `truncated`, and `synced_at`. Only a valid
marker with equal total/scanned counts and `truncated=false` authorizes a
whole-subject `local` or `auto` read. Legacy markers are not inferred or
upgraded: explicit catalog reads remain usable, while a whole-subject read
requires `sync --max-courses 0`. `changed` needs ≥2 syncs spanning the window
to be meaningful (fresh mirror reads as all-new).

## 8. Known gaps & honest caveats

- **`ccn` coverage is bounded** by what the district publishes as *offered*
  sections. It's an honest title-match alias finder (no fabricated crosswalk):
  it surfaces an alias only when both the legacy and CCN numbers are actually
  offered that term. Often returns "no alternate number offered this term."
- **Scorecard 71/100** — the low dims (`path_validity 0/10`, type-fidelity,
  cache-freshness) are *structural* for a single-endpoint HTML scraper, not
  functional problems. Don't try to "fix" them by scaffolding fake endpoints.
- **Cache disabled** by design (portal fetches aren't cheap; explicit `sync` is
  the model).
- **`compare-colleges` takes ~7s** — the portal serializes same-session requests,
  so a 9-college fan-out is inherently sequential-ish even with a faster limiter.
- **26 gosec findings remain in GENERATED files** (store.go/client.go/config.go/
  cliutil/cobratree) — generator retro candidates, not to be hand-patched.
- **Module/binary still named `laccd-class-search-pp-cli`** — see §9.
